# COST-7686 Gap Analysis: Implement application services

**Jira:** [COST-7686](https://redhat.atlassian.net/browse/COST-7686)
**Audited:** 2026-08-13 (refreshed 2026-08-16 on `feat/cost-7686-gaps`)
**Purpose:** Handoff audit vs ticket acceptance criteria. Does not update other trackers except the COST-7686 row in [docs/tasks.md](../tasks.md) when this file is refreshed.
**Beta scope:** Per [BETA-PRIORITY.md](BETA-PRIORITY.md) and [docs/tasks.md](../tasks.md), ROS/Kruize readiness and profile sizing are **not Cost beta blockers**. Ticket-owned Cost services (Koku API, Masu, Listener) **are** gated. ROS/Kruize Deployments are gated only when `spec.ros.enabled=true`.

## Verdict

COST-7686 application-service acceptance criteria are **met**, except **profile-based sizing (G4)** which remains a documented COST-7678 deliverable. Koku API/Masu/Listener, optional ROS API/Processor, and optional Kruize Deployment+Service+cluster RBAC (with finalizer cleanup) exist and are wired. Django key generation matches the ticket's 50-character/charset/create-once spec. `spec.ros.enabled=false` skips ROS/Kruize migrate, workloads, RBAC, NetworkPolicies, and ServiceMonitors (G1 closed). Ticket-owned Deployments are readiness-gated with a 5-minute timeout → `Degraded` + backoff (G2/G3 closed for this ticket). `spec.profile` is still unused.

## Done (meets or supersedes ticket intent)

- **Koku API** (`KokuAPIDeployment`/`KokuAPIService`), **Masu** (`MasuDeployment`/`MasuService`), **Listener** (`ListenerDeployment`) — [`internal/resources/koku.go`](../../internal/resources/koku.go). All wired with `KokuCommonEnv` (DB, cache, S3, Kafka, Django key, RBAC service, CA bundle) plus per-deployment env additions and `MergeEnv(spec.Env)` overrides.
- **ROS API** (`ROSAPIDeployment`/`ROSAPIService`) and **ROS Processor** (`ROSProcessorDeployment`) — [`internal/resources/ros.go`](../../internal/resources/ros.go). Applied from `reconcileWorkers` only when `ROSEnabled(cfg)`. DB/Kafka env, Kruize wait-for init container on the Processor, CA-bundle mount, liveness/readiness probes.
- **Kruize** — `KruizeDeployment`, `KruizeService`, `KruizeServiceAccount`, `KruizeConfigMap`, `KruizeClusterRole`, `KruizeClusterRoleBinding` in [`internal/resources/kruize.go`](../../internal/resources/kruize.go); cluster-scoped ClusterRole/Binding are deleted via the CR finalizer in `reconcileDelete()`, matching the COST-7681 finalizer pattern since ownerReferences cannot cross the cluster/namespace boundary.
- **Django secret key** — `djangoSecretKey(50)` in [`internal/resources/secrets.go`](../../internal/resources/secrets.go) uses `crypto/rand` and the exact charset `abcdefghijklmnopqrstuvwxyz0123456789!@#$%^&*(-_=+)` specified in the ticket (also matches COST-7694's charset fix). `DjangoSecret(cfg)` is applied via `r.ensureSecret()`, which is **create-only** — never regenerated on subsequent reconciles. Covered by [`secrets_test.go`](../../internal/resources/secrets_test.go) (`TestDjangoSecretKey_LengthAndCharset`, `TestDjangoSecretKey_Unique`, `TestDjangoSecret_HoldsGeneratedKey`).
- **Env vars from CR spec** — `KokuCommonEnv()` ([`internal/resources/env.go`](../../internal/resources/env.go)) reads directly from `cfg.Spec.*` and every Deployment additionally applies `spec.<component>.Env` overrides via `MergeEnv`.
- **Per-component resource overrides** — every component spec (`KokuAPISpec`, `MasuSpec`, `ListenerSpec`, `ROSAPISpec`, `ROSProcessorSpec`, `ROSPollerSpec`, `ROSHousekeeperSpec`, `KruizeSpec`) carries its own `Resources corev1.ResourceRequirements` field.
- **ROS opt-out** — `reconcileROSFeature` runs at the start of `reconcileCoreServices`. `ROSEnabled(cfg)` (default `false`) gates ROS migrate, Kruize objects + cluster RBAC, ROS workers, ROS NetworkPolicies, `KruizeServiceMonitor`, and the `ros-api` selector on `AppServiceMonitor`. Envoy ROS routes were already gated. Tests: [`core_services_test.go`](../../internal/controller/core_services_test.go), [`ros_cleanup_test.go`](../../internal/controller/ros_cleanup_test.go), [`monitoring_test.go`](../../internal/resources/monitoring_test.go), [`envoy_test.go`](../../internal/resources/envoy_test.go).
- **Readiness gate + 5-minute timeout** — shared `waitForDeployments` / `notReadyDeployment` / `readinessBackoff` in [`costmanagementserviceconfig_controller.go`](../../internal/controller/costmanagementserviceconfig_controller.go). See G2 closure below.

## Intentional deviations (do not treat as bugs)

| JIRA | Implementation | Rationale |
|------|----------------|-----------|
| Linear `Deploying`/`Ready` phase | `Phase{Pending,Progressing,Ready,Degraded}` derived from `Available`/`Progressing`/`Degraded` conditions | Documented Kubernetes-API-conventions deviation; see [design-vs-jira.md §1](../design/design-vs-jira.md#1-status-api-conditions-over-phase-enum). "Ungate the Platform phase" maps to `cfg.Status.Phase = PhaseReady` at the end of `reconcile()` once earlier stages return a zero `Result`. |
| ROS API/Processor treated as "application services" | Applied from the reconciler's internal "Workers" stage (`reconcileWorkers`), alongside Celery workers that COST-7687 owns | Cosmetic — internal pipeline staging, not a functional gap. Readiness for those two Deployments is still enforced in `waitForWorkerReadiness` when ROS is enabled. |
| Wait-path backoff after timeout (not from t=0) | Poll at `requeueSlow` (30s) until 5 minutes; then `Degraded` + backoff `30s → 1m → 2m → 5m` | Matches COST-7680's documented choice that constant polling is right *while* waiting; the ticket's backoff applies once the Deployment has failed to become Ready. |

## Closed gaps (was remaining on 2026-08-13)

| ID | Closure |
|----|---------|
| G1 `spec.ros.enabled=false` skipped nothing | Production gating restored in `5cff394`. This refresh also gates `KruizeServiceMonitor` and omits `ros-api` from `AppServiceMonitor` when ROS is off, so cleanup cannot be undone by the later monitoring stage. |
| G2 5-minute timeout / Degraded / backoff | `waitForDeployments` tracks `LastTransitionTime` on the waiting condition (same reason). After 5m: `Degraded=True` reason `DeploymentNotReady` with the component label, `Phase=Degraded`, `readinessBackoff`. Reason change resets the clock (`RemoveStatusCondition` before re-set — `SetStatusCondition` does not bump LTT on reason-only changes). |

| Related: untested Django/Kruize builders | `secrets_test.go` covers `djangoSecretKey` / `DjangoSecret`. `kruize_test.go` covers ServiceAccount, ConfigMap, Deployment shape, Service. ClusterRole tests were already in `kruize_rbac_test.go`. |

## Remaining gaps (ticket-scoped)

### G4. Profile-based sizing — confirmed pre-existing gap, still open

`spec.profile` (`Profile` type, `+kubebuilder:default:=standard`) is accepted by the API but never read by any resource builder in `internal/resources/`. This is already tracked as a cross-cutting gap in [COST-7678](COST-7678.md), [COST-7687](COST-7687.md), [COST-7689](COST-7689.md), [COST-7690](COST-7690.md), and `BETA-PRIORITY.md` T5 (ranked **P2 for beta**). Only `"standard"` is accepted; `"ha"` was removed to avoid a no-op API. Use per-component `spec.*.resources` fields until a shared sizing map lands in COST-7678 (`profiles.go`).
